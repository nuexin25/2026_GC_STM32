## 1. 赛题摘要（摘自《智能+工程创新赛道竞赛命题与运行》）

### 1.1 任务流程（决赛第一阶段）

1. 一键启动（启动后 5 秒内必须出发，全程自主运行，禁止遥控）；
2. 行驶至二维码板前读取任务码（如 `134+123+314+231`），并**显示在车体上部醒目位置的显示装置上**（字高 ≥12mm、亮光显示、不被遮挡）；
3. 前往**原料区**（电动转盘，φ300mm，3 个物料呈 120° 均布，转盘 6~10s/圈随机转动），按任务码顺序**逐个抓取**第一批 3 个物料（抓取 1 个放上小车后才能抓下一个）；
4. 运至**粗加工区**，按任务码放置到对应编号圆环；
5. 再将粗加工区的物料按顺序搬至**暂存区**对应圆环；
6. 返回原料区，重复上述流程完成**第二批** 3 个物料；第二批在暂存区**码垛**放置在第一批同色物料之上；
7. 完成后回到**启停区**，显示装置上需正确统计"抓取正确次数/放置正确次数"。

### 1.2 任务码格式

```
第一组三位数 + 第二组三位数 + 第三组三位数 + 第四组三位数
```

- 颜色编号：**红=1，黄=2，蓝=3，绿=4**
- 第一组：第一批 3 个物料的**颜色及搬运顺序**；
- 第二组：第一批物料在**粗加工区和暂存区**的放置位置（1/2/3 号圆环）；
- 第三组：第二批 3 个物料的颜色及搬运顺序；
- 第四组：第二批物料在**粗加工区**的放置位置；**暂存区码垛位置由第一批物料颜色决定**。
- 示例 `134+123+314+231`：第一批按 红→蓝→绿 搬运，分别放 1、2、3 号环；第二批按 蓝→红→绿 搬运，放粗加工区 2、3、1 号环。

### 1.3 关键场地参数

| 项目 | 参数 |
|---|---|
| 场地 | 2400mm × 2400mm，中间十字灰色行车道**宽 400mm**，其余浅色 |
| 启停区 | 蓝色，300×300mm，共 2 处，位置抽签确定 |
| 原料区 | φ300mm 电动转盘，高 80~100mm，3 物料 120° 均布，6~10s/圈 |
| 粗加工区/暂存区 | 580×150mm，表面有 1~6 号同心圆环（线宽 1.5mm），数字朝向场地中心 |
| 障碍物 | 黑色圆柱 φ50×100mm，数量与位置随机抽签 |
| 二维码板 | A4 横放，垂直安装于场地内侧，二维码 80×80mm 居中，位置随机 |
| 物料 | 3D 打印 ABS，≤80mm，≤100g；红黄蓝绿各 2 个 |

### 1.4 放置精度计分（每个圆环）

| 环号 | 1环(φ+3) | 2环 | 3环 | 4环 | 5环 | 6环 | 6环外/倾倒 |
|---|---|---|---|---|---|---|---|
| 分数 | 15 | 10 | 7 | 5 | 3 | 1 | 0 |

### 1.5 硬性规则（影响设计的红线）

- 外形：铅垂投影 ≤ **300×300mm**，高 ≤ **400mm**（出发状态，机械臂可折叠自行展开）；
- 只能使用**车载单一电源**，比赛全程（含调试）不得更换、不得遥控；
- 允许与笔记本电脑通讯（调试），但运行中不得触碰电脑；
- 运行中物料未放上小车**不得驶向下一区域**；不允许手爪夹持物料运送；
- 每轮调试 3 分钟、运行 3 分钟，仅一次启动机会；两轮取最好成绩。

## 2. 系统总体架构

```
                 ┌────────────────────────────────────────────┐
                 │              STM32F103VET6 (72MHz)          │
                 │                                             │
  HWT101CT ─USART2─▶ 航向角/角速度（闭环转向）                 │
  幻尔总线舵机 ─USART3─▶ 机械臂/执行机构（半双工）             │
  GM65 ────UART4──▶ 任务码字符串（134+123+314+231）           │
  上位机 ──UART5──▶ 全部参数调试输出                           │
  4×张大头 ──CAN───▶ 麦克纳姆轮底盘                            │
  OLED ────I2C1───▶ 调试显示                                  │
  LED×3 / 蜂鸣器 ─GPIO─▶ 状态指示                              │
                 └────────────────────────────────────────────┘
```

- **分工原则**：STM32 负责底盘运动控制、传感器采集、任务码解析显示与任务调度。
- **定位方案**：HWT101CT 航向角 + 步进电机编码器航迹推算（无灰度循迹传感器，靠灰色车道几何 + 视觉纠偏）。

| UART4 | PC10-TX / PC11-RX | 9600 | 8 / 1 / 无 | 已开 | **GM65 扫码模块**（TTL-232） |

### 3.2 GPIO 分配

| 引脚 | 标号 | 功能 |
|---|---|---|
| PA0 | LED_G | 绿色 LED（点亮电平视外接模块而定） |
| PA1 | LED_B | 蓝色 LED |
| PA2 | LED_Y | 黄色 LED |
| PA7 | BEEP | 蜂鸣器（**无源** WHT101，谐振 2.731kHz，经 NMOS AO3400A 驱动，栅极 R4 10K 下拉；PA7=TIM3_CH2 输出 ≈2.73kHz 方波、50% 占空比——电平直驱不发声，已实测确认） |
| PE7 | KEY1 | 按键 1，按下接 GND 为低电平 |
| PE8 | KEY2 | 按键 2，同上 |
| PE9 | KEY3 | 按键 3，同上 |
| PE10 | KEY4 | 按键 4，同上 |
| PE11 | KEY5 | 按键 5，同上 |
| PE12/PE13/PE14 | BZ_LED1~3 | 核心板板载 LED（经 1K 电阻接 3V3-2，**低电平点亮**，推挽输出，初始电平=高/上电熄灭）。功能分配：LED1=心跳指示（1Hz 与 alive 同步）、LED2=蜂鸣同步指示（鸣叫期间点亮）、LED3=预留（BSP_LED_Set 可控） |
| PA13/PA14 | SWDIO/SWCLK | SWD 烧录调试 |

⚠ 原理图核对备注（2026-09-05，依据 SCH_2026工创核心板；2026-09-06 上板实测更新）：
- KEY1~KEY5 为"按键→GND"接法，原理图无外部上拉电阻，**已改内部上拉 GPIO_PULLUP**（✅ 2026-09-06 代码已更新）；
- 蜂鸣器 WHT101 上板实测电平驱动**不响**，确认为无源器件 → 驱动方案改为
  **PA7=TIM3_CH2 PWM ≈2.73kHz 方波**（PSC=72-1，ARR=366-1，CCR=50%），详见 P0 修正记录；
- BZ_LED1~3 初始电平改 High（上电熄灭），并接入状态指示功能（心跳/蜂鸣同步/预留）。

### 3.3 供电

- **12V 电源外接板**：12V 锂电 → 步进电机驱动器（Emm_V5.0 供电范围见其说明书）；
- 核心板由电源板降压 5V→3.3V 供电；
- 各模块串口均为 3.3V TTL 电平，禁止接 RS232 电平。

驱动现状：

- `hwt101ct.c/h`：维特 HWT101CT 逐字节中断解析驱动（0x55 帧头，52=角速度 / 53=角度）；
- `oled.c/h`：I2C1 OLED 驱动（6×8 / 8×16 ASCII、中文、BMP）。

## 4. 分阶段开发计划

> 每阶段独立可验收，验收通过后再进入下一阶段（先建→烧录→看现象→记录）。

> 每阶段完成后按《调参手册》模板追加该模块文档（重要函数表、可调参数表、修改步骤、预期现象）。

### P0 工程框架与调试系统

**目标**：建立 printf 调试链路与心跳指示，为所有后续模块提供观测手段。

- 硬件连接：ST-Link → SWD（PA13/PA14）；USB-TTL 接 UART5：`模块TX→PD2(RX)`，`模块RX→PC12(TX)`，`GND共地`；LED_G/B/Y = PA0/PA1/PA2，蜂鸣器 = PA7；KEY1~KEY5 = PE7~PE11（按下为低电平，见 §3.2 上拉备注）。
- 变更记录 1：KEY1~KEY5 与板载 BZ_LED1~3 于 P0 验收后补入；按键扫描与应用自 P1 起使用（bsp_key 已实现，KEY 上拉已改 GPIO_PULLUP）。
- 变更记录 2（2026-09-06 上板修正）：蜂鸣器实测不响 → WHT101 为**无源**器件，PA7 由 GPIO_Output 改为 **TIM3_CH2 PWM**（≈2.73kHz、50% 占空比）；BSP_Beep 改为**非阻塞模式机**（times=0 持续鸣叫供故障报警）；BZ_LED 初值改 High 并分配状态指示功能（心跳/蜂鸣同步/预留）。详见调参手册 P0 章修订。
- 串口配置：UART5，115200-8-N-1，无流控。
- 开发内容：
  1. 重定向 `printf` 到 UART5（`fputc`/`__io_putchar`）；
  2. SysTick 心跳：LED 流水 + 1s 打印 `alive` 与系统时钟；
  3. 统一日志格式约定（模块名 + 数据），供上位机解析。
- 验收：上位机 1s 一条心跳；按键/代码控制 LED 与蜂鸣器有响应。

### P1 OLED 显示模块

**目标**：调通 I2C1 OLED，作为车载数据面板。

- 硬件连接：OLED SCL→PB6，SDA→PB7，VCC 3.3V，GND 共地（4 线 I2C，地址 0x78）；KEY1~KEY5 = PE7~PE11（P0 后补，本阶段增加按键切页）。
- 总线配置：I2C1，100kHz，7 位地址。
- 开发内容：封装显示页面接口（开机 Logo、航向角页、任务码页、统计页）；提供 `OLED_Printf` 风格接口；实现按键扫描（消抖）驱动 `bsp_key`，KEY1/KEY2 用于手动切换页面，与自动轮播互斥（手动切换后关闭轮播）。
- 验收：上电显示初始化页面；UART5 同步打印；显示无花屏、无卡顿（刷新 ≤50ms/帧）；KEY1/KEY2 切页可靠、无连跳。
- 备注：OLED 仅调试用。**赛题强制要求车顶任务码显示装置字高≥12mm**，需另选数码管/LCD 大屏，此为独立待办（见 §6 风险）。

### P2 HWT101CT 陀螺仪模块（USART2）

**目标**：稳定获取航向角 yaw 与 Z 轴角速度，为转向闭环提供反馈。

- 硬件连接：陀螺仪 TX→PD6(RX)，RX→PD5(TX)（可不接），VCC 3.3~5V（按模块说明书），GND 共地；模块水平安装于底盘中心，箭头方向与车头一致。
- 串口配置：USART2（PD5/PD6 重映射），**9600-8-N-1**，逐字节中断接收。
  - ⚠ 波特率必须与模块实际配置一致（驱动默认 9600；若模块出厂为 115200，用维特上位机改模块或改 `MX_USART2_UART_Init`）。
  - 建议将模块输出速率设为 100Hz（寄存器 0x03，值 0x09），静止 Z 轴自动校准开启。
- 开发内容：
  1. `stm32f1xx_it.c` 的 `USART2_IRQHandler` 中调用 `HWT101CT_UART_RxHandler()`；
  2. 提供角度接口：`float Get_Yaw(void)`（-180~180 连续化处理，可选 0~360 映射）；
  3. 上电静止 3s 自动校准零偏；UART5 每 100ms 打印 yaw/gyro_z。
- 验收：车体手动旋转 360°，OLED/上位机 yaw 跟随且累计误差 <2°；静置漂移 <0.5°/min。

### P3 步进电机驱动模块（CAN 总线）

**目标**：通过 CAN 控制张大头 Emm_V5.0 闭环驱动器，实现四轮独立速度/位置控制。

- 硬件连接：
  - STM32 CAN：PA11(CAN_RX)、PA12(CAN_TX) → CAN 收发器（TJA1050 等）→ CANH/CANL 总线（⚠ PA11/PA12 与 USB 数据脚复用，核心板 USB 口不可同时使用）；
  - 每个电机驱动器需插 **ZDT_CAN 模块**，全部挂同一总线，**总线两端各接 120Ω 终端电阻**；
  - 驱动器供电 12V（由 12V 电源板提供），与 MCU **共地**。
- 总线配置：CAN1 默认引脚 PA11/PA12（无重映射），**500kbps**（Prescaler=8, BS1=6TQ, BS2=2TQ），扩展帧，ExtId = `电机地址<<8 | 包序号`，校验字节默认 0x6B。
- 电机地址约定（驱动器菜单或指令设置）：

| 地址 | 部位 |
|---|---|
| 1 | 左前轮 |
| 2 | 右前轮 |
| 3 | 左后轮 |
| 4 | 右后轮 |
| 5 | 备用（原机械臂预留位，机械臂已改用总线舵机，见 P8） |
| 6 | 备用（同上） |

- 开发内容：
  1. 使能/失能、速度模式（0xF6）、位置模式（0xFD）、立即停止（0xFE98）、多机同步（0xFF66）封装；
  2. 轮径/细分配套参数（16 细分 3200 脉冲/圈）换算 RPM ↔ mm/s；
  3. 利用 CAN 反馈读取实时转速 `S_VEL`、位置 `S_CPOS`，实现里程计累计；
  4. UART5 周期打印四轮转速与里程。
- 验收：单轮指令启停/换向正确；四轮同步启停；给定 1000mm 位移实测误差 <1%。
- ⚠ 注意：`CAN_Transmit()` 中 `while(等待邮箱空闲)` 为死等，后续阶段改为超时返回，避免总线异常卡死主循环。

### P4 麦轮底盘运动学模块

**目标**：将 (Vx, Vy, ω) 分解为四轮转速，实现平移、横移、原地旋转。

- 硬件连接：S1 麦轮 ×4 按对角（X 形）布局安装，注意轮子滚花方向呈 X 形；电机轴与驱动器 42 步进对应。
- 配置：无新串口；依赖 P3 的 CAN 速度模式 + 多机同步。
- 开发内容：
  1. 麦轮运动学正/逆解（以轮距 L、轴距 W、轮径 R 为参数，写入参数表）；
  2. 速度斜坡限幅（加减速保护）；
  3. 接口：`Chassis_SetVelocity(float vx, float vy, float wz)`、`Chassis_Stop()`；
  4. UART5 打印目标/实际四轮转速。
- 验收：手柄/调试指令分别验证前进、横移、斜 45°、原地旋转四类动作方向正确；麦轮横移无明显跑偏。

### P5 GM65 扫码模块（UART4）

**目标**：读取二维码任务码字符串并解析为结构化任务。

- 硬件连接：GM65 TX→PC11(RX)，RX→PC10(TX)（可不接），VCC 5V（按模块手册），GND 共地；模块固定于车头，镜头对准竖直悬挂的二维码板（80×80mm，读距 4~25cm，见手册）。
- 串口配置：UART4（PC10/PC11），**9600-8-N-1**（GM65 出厂默认，波特率可扫设置码修改，其余参数不可改），TTL-232 电平。
- 模块建议配置（扫设置码或串口指令）：**连续识读模式**、输出后缀（如回车）便于定界、关闭不需要的条码类型只留 QR。
- 开发内容：
  1. 中断+空闲/超时成帧，提取任务码 ASCII（格式 `DDD+DDD+DDD+DDD`）；
  2. 校验格式合法性（4 组×3 位、分隔符'+'、颜色值 1~4）；
  3. 解析为结构体：第一批颜色顺序[3]、放置位[3]、第二批颜色顺序[3]、粗加工位[3]；
  4. OLED 显示任务码；UART5 打印原始帧与解析结果。
- 验收：对 80×80mm 二维码在 10~20cm 内 1s 内稳定输出；非法码被拒绝并报错。

### P7 运动控制综合（陀螺仪闭环 + 航迹推算）

**目标**：无循迹传感器条件下，实现精确走直线、定角旋转、点到点移动。

- 硬件连接：无新增（依赖 P2 陀螺仪 + P4 底盘）。
- 配置：无新串口。
- 开发内容：
  1. **航向闭环**：以 yaw 为反馈的 PID 旋转控制（ω 由角度环输出）；

| 4 | 腕部 |

## 附录A 幻尔总线舵机通信协议摘要（USART3）

> 完整文档见 `舵机总线/幻尔科技总线舵机通信协议1.pdf`。本附录为开发 AI 的实现依据摘要。
> 物理层：**半双工** UART 异步串行总线，**115200bps**，8 数据位，无校验，1 停止位；总线理论最多可挂 253 个舵机（链型）。

### A.1 指令包格式（上位机 → 舵机）

| 帧头 | ID 号 | 数据长度 | 指令 | 参数 | 校验和 |
|---|---|---|---|---|---|
| 0x55 0x55 | ID | Length | Cmd | Prm1…PrmN | Checksum |

- **ID**：0~253（0x00~0xFD），出厂默认 1；**254（0xFE）为广播 ID**：所有舵机执行但不应答（SERVO_ID_READ 除外，可用于单舵机总线上查询 ID）；
- **Length**：= 数据段字节数（含 Length 自身、Cmd、参数、校验和），即 **Length + 3 = 整包长度**；
- **Checksum**：`Checksum = ~(ID + Length + Cmd + Prm1 + … + PrmN) & 0xFF`（和取最低字节后按位取反）；
- **示例**：1 号舵机 500ms 匀速转到 500 码值（≈120°）：
  `55 55 01 07 01 F4 01 F4 01 0C`
  （角度 500=0x01F4→低 F4 高 01；时间 500ms=0x01F4→低 F4 高 01；校验 =~(0x01+0x07+0x01+0xF4+0x01+0xF4+0x01)&0xFF=~0xF3=0x0C）

### A.2 参数换算

| 参数 | 范围 | 换算 |
|---|---|---|
| 角度码值 | 0~1000 | 对应 **0~240°**，分辨率 0.24°/码；`码值 = 角度° × 1000 / 240` |
| 移动时间 | 0~30000ms | 设定时间内从当前角度**匀速**转到目标角度 |
| 偏差(offset) | -125~125 | 对应 ±30°，有符号数发送前强转 unsigned char |
| 电机模式速度 | -1000~1000 | 负值反转（发送前强转 unsigned short） |
| 电压限制 | 4500~12000mV | 越限 LED 闪烁并自动卸载 |

| 指令功能 | Cmd | Length | 参数说明 |
|---|---|---|---|
| SERVO_MOVE_TIME_WRITE 立即转动 | 1 | 7 | 角度低、角度高、时间低、时间高 |
| SERVO_MOVE_TIME_WAIT_WRITE 预设动作 | 7 | 7 | 同上，等待 MOVE_START 才执行 |
| SERVO_MOVE_START 执行预设 | 11 | 3 | 无（多关节同步起动的关键） |
| SERVO_MOVE_STOP 立即停止 | 12 | 3 | 停在当前角度 |
| SERVO_ID_WRITE 修改 ID | 13 | 4 | 新 ID（0~253，掉电保存） |
| SERVO_ANGLE_OFFSET_ADJUST 偏差即时调整 | 17 | 4 | -125~125（不保存） |
| SERVO_ANGLE_OFFSET_WRITE 保存偏差 | 18 | 3 | 无（掉电保存） |

### A.5 驱动实现注意事项（给开发 AI 的硬约束）

1. **半双工时序**：发送完成前不得进入接收判断；发送后立即开启接收，按 `0x55 0x55` 帧头同步，用 Length 字段定界；自身 RX 可能收到回显字节，一律按帧头重新同步过滤；
2. USART3 中断逐字节接收，缓冲区建议 ≥16 字节/帧，校验和错误整帧丢弃并累加错误计数（UART5 上报）；
3. **禁止连发**：同一舵机应答未收完（或广播指令后延时 ≥2ms）前不得发送下一条；
4. 多关节同步动作用 `WAIT_WRITE` 逐个预设 + 广播 ID(0xFE) 发 `MOVE_START` 同时起动；
5. 上电初始化顺序建议：`LOAD_OR_UNLOAD_WRITE(1 卸载)` → 设置角度限位 → `MOVE_TIME_WRITE` 慢速回初始位（时间 ≥500ms）→ `LOAD(1 装载)` 使能；
6. 抓取类动作前先 `SERVO_POS_READ` 校核实际位置，动作后再次校核，偏差超限走重试/报警流程。
